## Implemented

- A stable outside-React `NotebookSession` controls deliberate verified-account opening, writer ownership, namespace transitions, cloud callback fences, forced session loss and pending-work logout. It subscribes before reading the initial SDK session so stale startup results cannot restore a newer lost session.
- The existing local repository holds the single origin lease across views. Account repositories have immutable account IDs and borrow that lease; preview records never change ownership. Opening an account after reload remains deliberate. The session adapter uses the SDK token's session ID for refresh-stable callback identity; private RPCs still perform authorization independently.
- `AccountPanel` exposes configured sign-in/signup/reset forms, same-account reauthentication, local-notebook access, independent export and wait/cancel/logout actions. Missing public settings leave a usable local notebook and explanatory account panel. No real auth email was sent by this session.
- Complete bounded manifest validation and coherent body/version reads populate missing/stale clean account copies at startup. Local pending bodies, known old-epoch bases/outboxes, missing originals and conflicts are preserved. Same-epoch outboxes remain exact-retry candidates even if their accepted write is already visible remotely.
- The account editor mounts after cloud startup completes, preventing an old cached editor body from surviving a newer accepted cloud read. Clean remote replacement retains local generation rather than creating an upload intent. A queued acknowledgement never replaces newer editor text.
- Logout pauses user mutations while local writes and cloud sealing can finish. It calls explicit SDK local-scope signout only after both intents/outbox and uncommitted memory are resolved. Cancellation keeps the session and text usable. Secondary tabs send account/session-scoped control metadata to the writer. They never upload, clean a namespace or steal the lease.
- Session loss hides and pauses the account notebook synchronously, fences callbacks and retains its memory/disk copies. Export and unsaved-writing unload guards remain available on the paused screen, including after a local write failure. Opening failures after loading a verified-account cache also retain that cache on the exportable paused screen. A different account ID cannot satisfy same-account recovery, even if its email matches.
- Startup requests have a 15-second limit; failure retains local copies and fences late work. Account folders/Trash/imports are unavailable until the corresponding connected workflows exist. Account ZIP exports explicitly cover the captured device cache, not an independently complete cloud backup.
